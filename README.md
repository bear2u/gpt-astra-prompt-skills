# GPT-6 Astra 프롬프트 설계 스킬

사용자가 제공한 「GPT-6 Astra 프롬프트 작성법」을 바탕으로 만든 5개의 Codex 스킬입니다. 목표, 자율적으로 판단할 범위, 출력 형식, 검증 수준, 완료 조건을 명확하게 설계하는 데 사용합니다.

필요한 작업에 맞는 스킬 하나부터 선택하세요. 모든 스킬을 매번 호출하거나, 생성된 규칙을 모두 AGENTS.md에 추가할 필요는 없습니다.

## 현재 파일 위치

이 저장소에는 README와 5개 스킬의 본체가 함께 들어 있습니다. 각 스킬은 저장소 루트의 개별 폴더에 있으며, Codex에서 전역으로 사용하려면 해당 폴더를 환경의 스킬 디렉터리에 설치하거나 스킬 파일 경로를 직접 지정하세요.

각 스킬 폴더는 다음 구조를 가집니다.

```text
스킬 이름/
├── SKILL.md             # 호출 조건과 작업 절차
└── agents/
    └── openai.yaml      # 표시 이름, 설명, 기본 호출 문구
```

`astra-write-prompt`에는 필요할 때 읽는 `references/examples.md`도 있습니다. 현재 환경에서는 5개 스킬이 사용 가능한 스킬 목록에 등록된 것을 확인했습니다.

## 빠르게 시작하기

Codex의 대화 입력창에서 `$스킬이름` 뒤에 원하는 작업을 적으세요. 아래 예시는 터미널 명령이 아니라 대화에 입력하는 요청입니다.

```text
$astra-write-prompt 로그인 오류를 수정하는 코딩 에이전트용 프롬프트를 만들어줘.
기존 API 호환성을 유지하고, 관련 검증이 완료되면 종료하도록 해줘.
```

```text
$astra-audit-instructions 이 프로젝트의 AGENTS.md를 검토해줘.
중복되거나 충돌하는 규칙을 찾아 수정안을 제시하되, 파일은 아직 수정하지 마.
```

```text
$astra-scope-verification 현재 변경 사항에 필요한 검증을 실행해줘.
변경 영향에 맞춰 범위를 정하고 프로젝트 필수 검사는 유지해줘.
```

요청에는 가능한 범위에서 다음 정보를 함께 적으면 좋습니다.

- **대상:** 파일, 저장소, 기존 프롬프트 또는 수행할 작업.
- **목표:** 결과로 무엇이 달라져야 하는지.
- **제약:** 유지할 규칙, 수정 범위, 금지 행동.
- **요청 수준:** 분석·문안 작성만 필요한지, 파일 수정이나 실행까지 원하는지.
- **결과 형식:** 복사할 프롬프트, 표, 수정 파일, 짧은 보고 등.

정보를 모두 준비할 필요는 없습니다. 스킬은 맥락에서 확인할 수 있는 정보를 먼저 활용하고, 결과를 크게 바꾸는 누락 사항을 확인하도록 설계되어 있습니다.

## 어떤 스킬을 선택할까?

| 상황 | 선택할 스킬 | 주요 결과물 |
| --- | --- | --- |
| 작업 설명을 실행 가능한 프롬프트로 바꾸고 싶다 | `astra-write-prompt` | 복사해서 사용할 최종 프롬프트 |
| AGENTS.md나 스킬 지시가 길거나 충돌한다 | `astra-audit-instructions` | 감사 결과, 수정안 또는 수정된 파일 |
| 에이전트가 너무 자주 질문하거나 허용 범위를 넘는다 | `astra-define-autonomy` | AUTONOMY와 STOP 정책 문안 |
| 테스트가 과도하거나 필요한 검증이 불명확하다 | `astra-scope-verification` | 검증 계획 또는 실행 결과 |
| 여러 에이전트에 작업을 어떻게 나눌지 고민이다 | `astra-plan-delegation` | 역할 분담, 의존성, 통합 계획 |

## 1. astra-write-prompt — 프롬프트 작성

작업 설명에서 목표와 제약을 추출하고, 필요한 지시만 담은 프롬프트로 정리합니다. 출력 스타일과 독자 수준도 여기에서 다룹니다.

**주요 동작**

- 단순 작업에는 TASK, CONTEXT, REQUIREMENTS, OUTPUT 구조를 사용합니다.
- 여러 단계의 작업에는 필요한 경우 아래 8개 블록을 사용합니다.
- 중복된 일반론과 불필요한 전체 탐색·전체 테스트 요구를 정리합니다.
- 성공 여부를 관찰할 수 있는 검증 기준과 완료 조건을 넣습니다.

| 블록 | 정하는 내용 |
| --- | --- |
| GOAL | 달성할 결과 |
| CONTEXT | 필요한 배경과 입력 |
| PRIORITY | 적용할 지시와 프로젝트 규칙 |
| AUTONOMY | 스스로 진행할 범위와 확인할 상황 |
| TOOLS | 사용할 도구와 사용 조건 |
| OUTPUT | 독자, 형식, 길이 |
| VERIFY | 확인할 동작과 검증 범위 |
| STOP | 완료 조건과 진행 불가 시 보고할 내용 |

모든 블록이 필수는 아닙니다. 단순 요청에 형식을 맞추기 위해 불필요한 규칙을 추가하지 않습니다.

**사용 예시**

```text
$astra-write-prompt 다음 작업을 개발 에이전트용 프롬프트로 정리해줘.

작업: 장바구니에서 수량을 바꾸면 합계가 늦게 갱신되는 오류 수정.
제약: 기존 API와 디자인 유지. 관련 코드만 수정.
검증: 수량 증가·감소와 상품 삭제 후 합계 확인.
출력: 변경 내용과 검증 결과를 한국어로 짧게 보고.
```

```text
$astra-write-prompt 아래 고객 안내문 생성 프롬프트를 개선해줘.
독자는 비개발자이고, 결과는 Markdown 없는 순수 텍스트여야 해.
짧은 문단으로 작성하고 전문 용어는 필요한 경우에만 설명해줘.

[기존 프롬프트 붙여넣기]
```

**결과:** 복사할 최종 프롬프트와 필요한 경우 짧은 가정·변경 이유가 나옵니다. 프롬프트 작성 요청만으로 그 안에 적힌 구현 작업을 실행하지 않습니다.

## 2. astra-audit-instructions — 지시 파일 감사

AGENTS.md, system prompt, SKILL.md의 중복, 모호함, 충돌, 과도한 절차를 점검합니다. 프로젝트의 중요한 제약을 보존하면서 지시를 정리할 때 사용합니다.

**주요 동작**

- 요청된 파일과 관련 지시의 적용 범위를 확인합니다.
- 프로젝트 고유 제약과 일반 행동 반복을 구분합니다.
- 중복 규칙을 합치고, 실제로 동시에 적용되는 충돌을 찾습니다.
- 스킬의 상세 예시를 참조 문서로 분리할 필요가 있는지 확인합니다.
- 보안, 배포 승인, DB 변경, API 호환성, 아키텍처 등의 필수 규칙을 보존합니다.

**검토만 요청하기**

```text
$astra-audit-instructions 이 프로젝트의 AGENTS.md와 관련 스킬을 감사해줘.
중복·충돌·과도한 절차를 파일 위치, 문제, 영향, 제안으로 정리해줘.
파일은 수정하지 마.
```

**실제 수정까지 요청하기**

```text
$astra-audit-instructions AGENTS.md를 정리하고 수정해줘.
보안 정책, 배포 승인, 금지 라이브러리 규칙은 유지해줘.
일반 행동을 반복하는 문장은 합치고, 의미가 달라진 부분을 설명해줘.
```

**결과:** 감사 요청이면 발견 사항과 수정안, 수정 요청이면 실제 변경과 유지한 핵심 규칙을 보고합니다. 중요한 정책의 의무 여부가 불명확하면 임의로 삭제하지 않고 확인 항목으로 남깁니다.

## 3. astra-define-autonomy — 자율 실행 정책

에이전트가 일상적인 결정은 스스로 처리하면서 중요한 범위 변경과 권한 문제는 확인하도록 정책을 작성합니다.

**주요 동작**

- 허용된 행동, 수정 대상, 기존 승인, 되돌릴 수 있는 범위를 확인합니다.
- 범위 내 일상적인 결정과 결과를 크게 바꾸는 결정을 구분합니다.
- 같은 범위의 유효한 승인을 반복해서 요구하지 않도록 정리합니다.
- 작업 완료와 외부 의존성으로 인한 진행 불가를 구분합니다.

**사용 예시**

```text
$astra-define-autonomy 프론트엔드 개발 에이전트의 자율 실행 정책을 만들어줘.

기존 화면 안의 스타일 수정과 관련 코드 정리는 스스로 진행해도 돼.
새 의존성 추가나 화면 흐름 변경은 먼저 확인해야 해.
배포는 이번 작업 범위에 포함하지 않아.
AGENTS.md에 넣을 AUTONOMY와 STOP 문안으로 작성해줘.
```

**결과:** 짧은 AUTONOMY·STOP 문안이 나오며, 경계가 복잡하면 행동별 진행·질문 조건을 표로 정리합니다. 기본 결과는 정책 초안입니다. 실제 파일 반영까지 원하면 대상 파일과 적용 요청을 함께 적으세요.

## 4. astra-scope-verification — 검증 범위 설계

변경의 영향과 실패 위험을 기준으로 필요한 검증을 선택합니다. 단순히 테스트 수를 줄이는 것이 아니라, 주요 회귀를 잡는 검증과 종료 기준을 구체화합니다.

**검증 판단의 예**

| 변경 유형 | 고려하는 검증 |
| --- | --- |
| 색상·문구 | 관련 화면과 표시 상태 확인 |
| 계산·상태 처리 | 관련 단위 테스트와 경계값 |
| 인증·결제·데이터 | 권한, 실패 경로, 관련 통합 검증 |
| 공유 모듈·API·스키마 | 호출자 영향과 호환성 |

실제 선택은 diff, 프로젝트 규칙, 기존 검증 도구를 기준으로 합니다. 변경 줄 수가 적어도 결제나 권한에 영향을 주면 검증 범위가 커질 수 있습니다.

**계획만 요청하기**

```text
$astra-scope-verification 현재 diff를 보고 검증 계획을 세워줘.
각 검사가 어떤 회귀를 잡는지 설명하고, 아직 실행하지 마.
프로젝트에서 확인한 명령만 제안해줘.
```

**검증 실행 요청하기**

```text
$astra-scope-verification 현재 변경 사항을 검증해줘.
관련 회귀를 확인하는 기존 검사를 실행하고 필수 CI 규칙은 유지해줘.
이번 변경 때문에 발생한 실패는 수정하고 다시 확인해줘.
실행하지 못한 항목은 구분해서 보고해줘.
```

**결과:** 검증 항목, 실행 여부, 결과, 다루는 위험을 보고합니다. 성공한 검사를 이유 없이 반복하거나 확대하지 않으며, 필수 검사를 임의로 생략하지 않습니다.

## 5. astra-plan-delegation — 병렬 위임 설계

독립적으로 수행할 수 있는 작업을 분리하고, 각 담당 범위와 결과 통합 방식을 정합니다.

**주요 동작**

- 작업 사이의 선행 조건과 입력·출력 관계를 확인합니다.
- 독립 조사나 서로 다른 문서 검토를 병렬 작업으로 분리합니다.
- 같은 파일을 동시에 수정하지 않도록 쓰기 책임을 정합니다.
- 주 에이전트가 결과의 근거, 모순, 누락을 확인하고 통합하도록 설계합니다.
- 위임 비용이 더 크거나 도구가 없으면 단일 에이전트 방식으로 조정합니다.

**계획만 요청하기**

```text
$astra-plan-delegation 미국·한국 시장과 경쟁 제품 가격을 조사하려고 해.
독립적으로 조사할 범위, 각 결과물 형식, 통합 기준을 설계해줘.
지금은 계획만 작성하고 서브에이전트는 실행하지 마.
```

**실행까지 요청하기**

```text
$astra-plan-delegation 이 저장소의 프론트엔드와 백엔드를 각각 읽기 전용으로 분석해줘.
독립적인 부분은 사용 가능한 서브에이전트에 위임해 실제로 진행해줘.
주 에이전트가 API 연결 지점의 불일치를 확인하고 최종 결과를 통합해줘.
파일은 수정하지 마.
```

**결과:** 작업·담당 범위·선행 조건·산출물 표와 통합 절차가 나옵니다. 실행은 명시적으로 요청했고 현재 도구와 상위 지시가 허용하는 경우에 진행합니다. 계획 작성만으로 에이전트가 실행되지는 않습니다.

## 여러 스킬을 함께 사용하는 방법

순서는 작업에 따라 선택하세요. 앞 단계 결과를 같은 대화에서 다음 요청의 입력으로 사용할 수 있습니다.

### 기존 프로젝트의 지시 정리

1. `astra-audit-instructions`로 기존 규칙을 점검합니다.
2. 질문·승인 문제가 있으면 `astra-define-autonomy`로 정책을 보완합니다.
3. 검증 범위가 모호하면 `astra-scope-verification`으로 기준을 정합니다.
4. 실제 파일에 적용하려면 대상 파일과 수정 범위를 명시해 요청합니다.

### 새 작업용 프롬프트 만들기

1. `astra-write-prompt`로 기본 프롬프트를 작성합니다.
2. 작업이 크고 독립적인 부분이 있으면 `astra-plan-delegation`으로 분담 계획을 작성합니다.
3. 앞서 정한 정책 중 필요한 부분만 최종 프롬프트에 반영합니다.

예를 들어 같은 대화에서 다음과 같이 이어갈 수 있습니다.

```text
$astra-write-prompt 방금 만든 자율성 정책과 검증 기준을 반영해서
이 작업의 최종 실행 프롬프트를 작성해줘.
중복 지시는 합치고, 병렬 위임은 독립적인 작업에만 적용해줘.
```

## 자주 묻는 질문

### 프롬프트를 만들면 실제 작업도 실행되나요?

`astra-write-prompt`의 기본 결과는 프롬프트입니다. 구현까지 원하면 후속 요청으로 “이 프롬프트에 따라 실제로 구현해줘”라고 명시하세요.

아닙니다. 원하는 결과에 가장 가까운 스킬 하나로 시작하세요. 단순한 버튼 변경에 별도 위임 계획이나 자율성 정책 설계까지 할 필요는 없습니다.

### 스킬이 인식되지 않으면 어떻게 하나요?

현재 환경의 스킬 디렉터리에 해당 폴더와 `SKILL.md`가 있는지 확인하세요. 이 저장소에서 직접 참조할 때는 아래처럼 저장소 경로를 지정할 수 있습니다.

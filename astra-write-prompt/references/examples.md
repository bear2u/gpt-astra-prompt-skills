# 프롬프트 구성 예시

## 작은 수정

```text
TASK
기존 버튼의 배경색을 제공된 색상으로 수정한다.
CONTEXT
사용자가 지정한 컴포넌트와 기존 디자인 규칙을 기준으로 한다.
REQUIREMENTS
변경 범위를 해당 버튼으로 제한하고 기존 동작을 유지한다.
OUTPUT
변경 파일과 화면 확인 결과를 짧게 보고한다.
```

색상이나 대상이 없으면 맥락에서 찾고, 찾지 못하면 필요한 값을 확인한다.

## 여러 단계의 구현

```text
GOAL
합의한 요구사항의 사용자 흐름을 실제로 동작하게 구현한다.
CONTEXT
대상 저장소, 요구사항, 기존 구현과 프로젝트 제약을 기준으로 한다.
PRIORITY
상위 지시를 준수하고 현재 요청과 적용 가능한 프로젝트 규칙을 따른다.
AUTONOMY
범위 내 일상적이고 되돌릴 수 있는 결정은 진행한다.
결과를 크게 바꾸는 모호함이나 새로운 권한이 필요한 행동은 확인한다.
TOOLS
기존 개발·검증 도구를 사용한다. 외부 작업 권한은 별도로 추정하지 않는다.
OUTPUT
구현 결과, 변경 이유, 검증 결과와 미완료 사항을 보고한다.
VERIFY
변경으로 생길 수 있는 주요 회귀를 확인하고 필수 프로젝트 검사를 수행한다.
STOP
합의한 흐름이 동작하고 필요한 검증이 통과하면 마친다.
필수 입력이나 외부 의존성으로 막히면 완료한 부분과 필요한 조치를 보고한다.
```

사용할 때 “합의한 흐름”을 실제 요구사항으로 바꾸고 검증 명령과 성공 조건을 프로젝트에서 확인해 구체화한다. 알 수 없는 명령을 임의로 채우지 않는다.
